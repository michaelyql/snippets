Memory Management​

Theory​

  • Each process has its own virtual (logical) address
  • All virtual memory accesses go through the memory management unit (MMU) of the CPU to translate it to a physical RAM address
  • The translation step is expensive, so the MMU uses a Translation Lookaside Buffer (TLB) to cache recently translated addresses
  • Memory is divided into small, fixed size memory pages
  • Each page frame in physical RAM can be mapped on to by different process's memory pages
  • The MMU uses the higher bits of the virtual address to index into page tables to find the mapped frame and the lower bits for the offset into the frame
  • If the memory page is not in RAM, the MMU raises a page fault. The OS loads the page from disk into ram, updates the page table, and lets the CPU retry the instruction. This is demand paging.
  • If there was previously a page in the frame, it is evicted via page replacement policies (LRU, FIFO)
  • Linux allows selecting the page size at compile time. The page size differs between architectures.

Sysadmin Tools​

  • find
    • Syntax: find [starting directory] [expression] [action]
    • E.g. 
      === By name ===
      find . -name "file.txt" (exact name)
      find /home -iname "photo.jpg" (case insensitive)
      find . -name "*.pdf" (wildcard)

      === By type === 
      find /var -type d  (directory)
      find /etc - type f  (file)
      find . -type l  (symlink)

      === By size === 
      find . -size 100M (exactly 100mb)
      find . -size +1G (more than 1gb)
      find . -size -10k (less than 10kb)

      === By date/time
      find . -mtime -1 (last 24 hrs) 
      find . -atime +30 (more than 30 days ago)
      find . -cmin -10 (last 10 mins)

      === Actions === 
      find . -name "*.tmp* -delete 
      find . -type d -exec chmod 755 {} +
    • Good practices
      • Chosose an explicit search root, predicates such as name, type, owner, size, or modification time, and safe handling of matched paths
      • Preview matches before any action and avoiding broad or unquoted destructive commands
  • ps
    • ps = Process Status. Provides snapshot of active processes, their process IDs (PIDs), CPU and memory usage, and the command that started them
    • ps -ef: List every process with full details
    • ps aux: List all process for all users
    • Key flags:
      • -e or -A: selects all processes
      • -f: Full formati listing
      • a: shows processes for all users when accompanied by x flag
      • u: Displays user-oriented format (including CPU and memory usage percentages)
      • x: Includes processes without a controlling TTY (like background daemons)
      • Find a process by name: ps aux | grep nginx
      • Sort process by highest memory usage: ps aux --sort=-%mem
      • Sort process by highest CPU usage: ps aux --sort=-%cpu
      • View a user's process: ps -u username
      • See hierarchical tree view of processes: ps -ef --forest (only on Linux/BSD)
  • top
    • Good practices
      • Use ps for a point-in-time process snapshot and top for an updating view of CPU, memory, state, and load
      • Confirm the exact PID, owner, command, parent, start time, and relevant resource signal rather than matching a name alone
  • kill
    • kill sends a signal, normally SIGTERM , rather than directly guaranteeing termination
    • Prefer a graceful, narrowly targeted stop, verifying the result, and reserving SIGKILL for justified escalation
  • Parsing ps | grep
    • ps | grep performs string-based pattern matching on a messy, unstructured human-readable line, whereas explicit field selection (-o) and pgrep are structured, deterministic data queries.

Syscalls​

  • invokes the kernel, passes control over to kernel to perform some predefined work
  • kernel controls hardware and provides interface / abstraction to perform memory management, process management, file operations, disk I/O, device I/O, networking
  • userspace library is a wrapper around the actual syscall which fills the registers with the correct values

popular syscalls

  • file
    • open, read, write, close, stat/fstat/lstat, lseek, poll, select, dup, fcntl, fsync, flock, truncate
  • memory
    • mmap, munmap, brk, sbrk,
  • ipc
    • shmget, shmat, shmctl, shmdt, pipe, semget, semop, semctl,
  • process
    • getpid, fork, execv (and variants), exit, kill, ptrace, times, mlock, munlock, sched_setaffinity, sched_getaffinity
  • system
    • uname, getcwd, mkdir, rmdir, creat, link, unlink, symlink, chmod, chown, umask, gettimeofday, sysinfo, utime, ustat, chroot, time
  • network
    • socket, bind, listen, accept, connect, send, recv, sendmsg, recvmsg, shutdown, getsockname, getpeername, setsockopt, getsockopt
  • kernel dev
    • create_module, init_module, delete_module, query_module, get_kernel_syms
  • i/o
    • io_setup, io_destroy, io_getevents, io_submit, io_cancel, epoll_create, epoll_ctl, epoll_wait, io_uring_setup, io_uring_register

core concepts

  • file descriptors: everything is a file - regular files, directories, devices, process info, pipes and sockets
    • after considering file permissions, read/write syscalls, you can interact with 80% of the OS
    • you can use tools to redirect input as well
  • processes and fork-exec
    • fork clones the process (almost identical), exec replaces the current process with a new one (replaces env variables)
  • filesystem
    • root is at /, /home is user data, /etc/ is system wide configs, /var/ is variable data (e.g. logs, caches), /tmp/ is temporary files, /usr/bin/ is user-installed binaries
  • file permissions
    • every file has Owner, Group, Others with Read(r) Write (w) Execute (w) permissions
    • uid 0 (root) superuser can bypass all permissions
    • sudo runs a command with root privileges
  • shell and exit codes
    • shell is main way to the kernel
    • every command has exit code, 0=success, everything else=failure
    • pipes allow to chain stdout of one process to stdin of another
  • signals (software interrupt)
    • signals are sent to processes e.g. sigterm (15, "polite shutdown"), sigkill (9, forceful kill), sigint (2, ctrl+c) etc.
  • standard streams (stdin, stdout, stderr)
    • every program has three data streams, 0 stdin, 1 stdout, 2 stderr
    • stdout is buffered (waits for newlines), stderr is unbuffered (prints immediately)
    • redirect using >
  • kernel vs user space
    • code runs in user space. when user needs hardware, it makes a syscall, pass control to kernel to run in kernel space
    • strace lets you see every syscall the program makes

tools

  • ps auxf
    • show all running processes and their tree hierarchy
  • lsof -i :8080
    • list all open files, show which process is using port 8080
  • htop
    • shows CPU, memory, load average (no. of processes waiting for CPU or disk I/O)
