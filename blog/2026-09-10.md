learning some new stuff and revising already learnt concepts

- `char` and `signed char` are distinct types, so `std::is_same::value<char, signed char>` is always `false`, even though `char` can be implemented as a signed type
- [nested namespaces](https://en.cppreference.com/cpp/language/namespace) were added in C++17
    - `namespace A::B::C { ... }` is equivalent to `namespace A { namespace B { namespace C { ... } } }` 
    - just an easier way to declare nested members in a more compact way  {/* truncate */}
- prefer smart pointers as the default way to manage memory safely, versus manually alloc/dealloc using new/delete and malloc/free
    - `std::make_shared<T>(args...)` provides a single memory alloc as compared to `std::make_shared<T>(new T(args...))`. But prior to C++17 it did not provide exception safety against the case `foo(std::make_shared<T>(new T(args...)), throwing_func())`, as the evaluation of function arguments are unsequenced, so `new T` can run and construct the object, then an exception is thrown in `throwing_func()` before the shared pointer is created, so memory is leaked
    - Since C++17, arguments are guaranteed to be completely evaluated before evaluating another, i.e. their evaluations cannot interleave. Though their order of evaluation is still indeterminately sequenced. So this prevents the memory leak scenario above
- the four exception safety levels are nothrow, strong, basic, none
    - none means anything can happen if an exception is thrown - i.e. invariants can be broken, memory may leak. object state and resources are not guaranteed. but, this is **not** the same as UB.
        - the stack simply unwinds, destructors are called until it reaches a scope that handles the exception or otherwise it is uncaught
    - basic means if an exception is thrown, there is still no memory leaks, and invariants still hold true about object classes. but we don't know the state or value of the objects. though we can still use and destroy them
    - strong means, if an exception is thrown, the object is left in the state it was prior to the operation
    - nothrow means the function does not let an exception escape (propagate) outside its scope. If it still throws, `std::terminate` is called. 
- `const char* ptr = "Next"; *ptr++;`
    - this prints `N`. ++ has higher operator precedence, but it returns the original value of the pointer before the increment. then that address is dereferenced so it prints `N`.
