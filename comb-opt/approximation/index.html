Combinatorial Optimization

Overview​

Combinatorial optimization can be thought of as finding the best combination of a set of choices to maximize or minimize some outcome.

Many of these problems are NP-hard and don't have an exact, efficient solution unless P=NP, so we have to sacrifice (relax) one of optimality (finding the best solution), generality (works for all instances) or efficiency (computable in polynomial time).

Definitions​

An α\alphaα-approximation algorithm for an optimization problem is a polynomial time algorithm that, for all instances of the problem, produces a solution whose value is within a factor of α\alphaα of the value of an optimal solution.

α\alphaα is also called the performance guarantee, the approximation ratio or approximation factor. A convention is that α>1\alpha>1α>1 for minimization problems, and α<1\alpha<1α<1 for maximization problems.

E.g. a 12\frac{1}{2}21​-approximation algorithm for a maximization problem is a polynomial-time algorithm that always returns a solution whose value is at least half the optimal value.

A polynomial-time approximation scheme (PTAS) is a family of algorithms Aϵ{A_\epsilon}Aϵ​, where there is an algorithm for each ϵ>0\epsilon > 0ϵ>0, such that AϵA_\epsilonAϵ​ is a (1+ϵ)(1 + \epsilon)(1+ϵ)-approximation algorithm (for minimization problems) or a (1−ϵ)(1 − \epsilon)(1−ϵ)-approximation algorithm (for maximization problems).

Some problems are very hard and do not have a PTAS unless P=NP. Max-clique is one such problem. It tries to find S⊆VS\subseteq VS⊆V that maximizes ∣S∣|S|∣S∣ s.t. for each i,j∈Si,j\in Si,j∈S, (i,j)∈E(i,j)\in E(i,j)∈E.

Linear Programming​

Linear Programming (LP) can be used to solve combinatorial optimization problems. Most of these problems only allow integer solutions and not fractional ones, so common strategies are to 'relax' an integer program (IP) into a LP which can be solved in polynomial time, and then rounding the values to obtain an integer solution within a certain factor of the optimal solution.

Each linear program or integer program is formulated in terms of some number of decision variables that represent some sort of decision that needs to be made. The variables are constrained by a number of linear inequalities and equalities called constraints. Any assignment of real numbers to the variables such that all of the constraints are satisfied is called a feasible solution.

In addition to the constraints, linear and integer programs are defined by a linear function of the decision variables called the objective function. The linear or integer program seeks to find a feasible solution that either maximizes or minimizes this objective function. Such a solution is called an optimal solution.

The value of the objective function for a particular feasible solution is called the value of that solution. The value of the objective function for an optimal solution is called the value of the linear (or integer) program. We say we solve the linear program if we find an optimal solution

Linear programs do not require that decision variables are integers, and are polynomial-time solvable.

LP Duality - Primal & Dual​

The dual of a linear program is the 'mirror image' of the original problem (the primal). Every LP has a corresponding dual LP.

The dual provides a different perspective: while the primal looks for the optimal allocation of resources, the dual looks for the optimal valuation of those resources.

Imagine you are a factory owner (the primal). You want to maximize profit by deciding how many products to make, given limited materials (labor, steel, electricity).

The dual asks a different question: "If a competitor wanted to buy all your raw materials instead, what is the minimum price you should charge per unit of each material to ensure you make at least as much money as you would by manufacturing the products?"

The variables in the dual represent the shadow prices (or marginal values) of each resource constraint in the primal.

To take the dual, you must first write the primal in a standard inequality form.

Primal (Standard Maximization Form):

  • Objective: Maximize cTxc^TxcTx
  • Constraints: Ax≤bAx\leq bAx≤b
  • Variables: x≥0x\geq 0x≥0

Dual (Standard Minimization Form):

  • Objective: Minimize bTyb^TybTy
  • Constraints: ATy≥cA^Ty\geq cATy≥c
  • Variables: y≥0y\geq 0y≥0

(Note: If the primal is a minimization problem with ≥\geq≥ constraints, the dual becomes a maximization problem with ≤\leq≤ constraints.)

The general rule for conversion: a primal constraint becomes a dual variable, and a primal variable becomes a dual constraint.

While in this case there is a simpler and faster approximation algorithm that achieves a better performance guarantee, sometimes randomized algorithms are simpler to describe and analyze than deterministic algorithms.

In fact, most of the randomized algorithms we present in this book can be derandomized: that is, a deterministic variant of them can be created that achieves the expected performance guarantee of the randomized algorithm.

However, these deterministic algorithms are sometimes more complicated to describe. In addition, there are some cases in which the deterministic variant is easy to state, but the only way in which we know how to analyze the algorithm is by analyzing a corresponding randomized algorithm
