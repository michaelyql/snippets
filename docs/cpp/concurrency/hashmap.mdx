# Hashmaps

- Main idea: Each bucket is a linked list with its own mutex (fine grained locking). When the linked list grows too long, convert it to a balanced tree 
    - Good if the table isn't resized 
- Lock striping: one lock is assigned to a range of buckets (not resized)
- Thin locks: if level of contention is expected to be low, use lightweight locking mechanism: CAS + busy wait, calling yield if can't obtain lock after certain number of tries
- Reader/writer lock: allow multiple readers or single writer at a time for a bucket
- Safe reclamation with hazard pointers (see Folly implementation)
- To handle resizing:
    - (Naive method) Use a global lock / have one thread lock all mutexes, create new hash table of bigger size, copy data over, then unlock all mutexes / global lock

## Java ConcurrentHashMap

- Pre Java 8, the map was split into smaller chunks (segments) each with its own lock
- Post Java 8, the map uses CAS, fine-grained synchronization, and linked list per bin turns into trees when the bin grows too big
- Reads are almost always lock-free 
- Writes use fine-grained locking + CAS
- Resizing is handled by multiple threads
