# Basics

## Decorators

A decorator is a function that takes another function, extends or modifies its behavior, and returns a new function.

They are commonly used for logging, authorization, timing, caching, and validation.

```python
def announce(func):
    def wrapper():
        print("Starting function...")
        func()
        print("Function finished.")

    return wrapper

@announce
def greet():
    print("Hello!")

# equivalent to
# greet = announce(greet)

greet()
```

The decorator replaces `greet` with the returned wrapper function.

Use `*args` and `**kwargs` so the decorator works with arbitrary functions:

```python
from functools import wraps

def log_call(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        result = func(*args, **kwargs)
        print(f"Result: {result}")
        return result

    return wrapper

@log_call
def add(a, b):
    return a + b

add(2, 3)
```

A decorator can itself receive arguments:

```python
from functools import wraps

def repeat(times):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result

        return wrapper

    return decorator

@repeat(3)
def say_hello():
    print("Hello")

say_hello()
```

## Generators

A generator is a special kind of iterator that produces values lazily, one at a time.

A function becomes a generator when it contains `yield` instead of (or in addition to)  return.

```python
def count_up_to(n):
    i = 1
    while i <= n:
        yield i
        i += 1

numbers = count_up_to(3)

print(next(numbers))  # 1
print(next(numbers))  # 2
print(next(numbers))  # 3
```

After yielding a value, the generator pauses. The next call to `next()` resumes execution from where it stopped.  When there are no more values, Python raises StopIteration.

Usually, generators are consumed with a `for` loop:

```python
for number in count_up_to(3):
    print(number)
```

Generators are useful because it produces values only when needed: 

```python
# generator
squares = (x * x for x in range(1_000_000))
for square in squares:
    print(square)

# versus list (stores all values in memory)
squares = [x * x for x in range(1_000_000)] 
```

Generator for reading a large file:
```python
def read_lines(filename):
    with open(filename) as file:
        for line in file:
            yield line.strip()

for line in read_lines("large_file.txt"):
    print(line)
```

Generators can be chained together:
```python
def numbers():
    for i in range(10):
        yield i

def even_numbers(values):
    for value in values:
        if value % 2 == 0:
            yield value

def squares(values):
    for value in values:
        yield value * value

result = squares(even_numbers(numbers()))

for value in result:
    print(value)
# 0 4 16 36 64
```

Each stage processes values lazily.

## Concurrency

### Global Interpreter Lock

The **Global Interpreter Lock** (GIL) is a mutual-exclusion lock used by interpreters like CPython to ensure that only one thread executes Python bytecode at any given time
- The lock allows only a single native thread to control the interpreter per process
- Even on computers with multiple CPU cores, multi-threaded Python code cannot run tasks in true parallel.
- It protects internal data structures and memory management, specifically reference counting, from unsafe concurrent changes

Impact on performance
- CPU-Bound tasks such as heavy calculations and data processing run slower in multi-threaded programs because threads wait for their turn to use the interpreter. 
    - Developers often use separate processes via `multiprocessing` to bypass this.
- I/O-Bound tasks such as network requests and file reads release the lock while waiting for a response
    - This allows multi-threading to handle concurrent waiting tasks efficiently

    for i in range(count):
        print(name, i)

# Thread Pool
from concurrent.futures import ThreadPoolExecutor

def work(x):
    return x * x

with ThreadPoolExecutor(max_workers=4) as executor:
    futures = [executor.submit(work, x) for x in range(5)]
    results = [future.result() for future in futures]

with ThreadPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(work, range(5)))

    global counter

    with lock:
